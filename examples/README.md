# Example `lib-conf` usage

## Structure

Examples are structured in sub-directories, each of which contain:
- Exactly 1 `lib` crate
  - These showcase how libraries can provide a configuration API using `lib-conf`.
- 1 or more `bin` crates
  - These showcase how dependant crates benefit from using structs generated by `lib-conf`.

Each sub-directory / `lib` provides a notable, distinct implementation pattern - with the most common applications provided in the first examples, and the more 'niche' use-cases covered by latter examples.

## Quick breakdown

Example | Description
------- | -----------
`readme` | This is the resulting code from the README.md demo
`1-typical` | Typical usage in a library where `serde` is a mandatory dependency
`2-serde-optional` | Usage in a library where `serde` support is feature-gated
`3-req-fields` | Similar to #1, but has some fields that are mandatory (no default, non-`Option`)
`4-generics` | Contains a `Config` struct that, for whatever reason, requires generics
`5-req-override` | Provides a `Config` struct with a field that *can only* be initialized **at run-time**
